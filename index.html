Toy ECC, the Caesar Cipher and Two Attacks

Based on the toy curve from Part 1

This report uses the toy elliptic curve from Part 1 to encrypt and decrypt a message, repeats the exercise with the Caesar cipher, and compares the two schemes. It then describes a statistical attack on the Caesar cipher and an attack on the toy ECC scheme that exploits its small private key. All results were obtained with a Python script written for this purpose.

1. The toy curve

The curve is y² = x³ + 7 over the prime 17, with generator G = (1, 5). Repeated addition of G gives the following points:

k123456789
kG(1, 5)(2, 10)(5, 9)(12, 1)(12, 16)(5, 8)(2, 7)(1, 12)∞

Since 9G is the point at infinity, G has order 9 and the private key d is a number from 1 to 8. The public key is Q = dG. The real secp256k1 curve has about 2256 possible keys. Because 9 is not prime, multiples of 3 are avoided as keys: they would place the shared point in a subgroup of only three points.

2. Encryption with the toy ECC scheme

A text message cannot easily be mapped to a point on such a curve, so the curve is used to agree on a shared point, which is then hashed to produce a key stream that is XORed with the message (the idea behind ECIES).

Encryption (the sender knows Q):

  1. Choose a one-time random number r.
  2. Compute R = rG, which is sent with the ciphertext.
  3. Compute the shared point S = rQ.
  4. Hash S with SHA-256 to obtain a key stream of the message length.
  5. Ciphertext = message XOR key stream.

Decryption (the receiver knows d): compute S = dR, derive the same key stream and XOR it with the ciphertext. Both sides obtain the same S because dR = d(rG) = r(dG) = rQ.

Role of the keys. The private key d is secret and is needed to decrypt. The public key Q is published and allows anyone to encrypt for the receiver. The value r is used once per message, so that each message has a different key stream, and R transmits the information the receiver needs to recompute S.

3. The Caesar cipher

With letters numbered A = 0 to Z = 25, encryption is (x + k) mod 26 and decryption is (y − k) mod 26. With k = 3:

ciphertext : Dwwdfn dw gdzq
decrypted  : Attack at dawn

4. Comparison of the two schemes

KeysOne secret key kPrivate key d, public key Q, one-time key r
EncryptionShift each letter by kCompute S = rQ, hash it, XOR with the message
DecryptionShift each letter by −kCompute S = dR, hash it, XOR with the ciphertext
Key space25 useful keys8 private keys (6 if multiples of 3 are excluded); about 2256 for the real curve

Similarities. Both schemes treat each symbol separately, so changing one plaintext letter changes only one ciphertext symbol. Both are reversible with the key, and in these toy versions both have a key space small enough to be searched exhaustively. Differences. Caesar is symmetric, while the ECC scheme is public-key. Caesar applies the same shift to every letter, whereas the ECC scheme uses a different key stream byte at every position.

To compare the statistical properties, 20,000 bytes of English text were encrypted with both schemes (the index of coincidence is the probability that two random bytes are equal; it is about 0.004 for random data).

The Caesar ciphertext has exactly the same statistics as the plaintext, since the letter frequencies are only moved to other letters. This is what the statistical attack exploits. The ECC ciphertext looks random, but this is due to the SHA-256 key stream and not to the curve itself: the points kG only take 4 different x values (1, 2, 5 and 12).

5. Statistical attack on the Caesar cipher

With only 25 keys, an exhaustive search is always possible. The task is to decide automatically which candidate is the correct text, using statistics of English computed from a corpus of 1,885,407 letters from three public-domain books (Emma, Moby Dick, The Man Who Was Thursday). The most frequent letters in the corpus are E, T, A, O, N, I. Three methods were compared:

  1. Most common letter. The most frequent ciphertext letter is assumed to be E.
  2. Chi-square. The shift whose letter counts are closest to the English frequencies is chosen.
  3. Bigram score. The shift whose pairs of adjacent letters are most typical of English is chosen.

The methods were tested on three other books (Alice in Wonderland, Hamlet, Persuasion), using 900 random text pieces of each length, each encrypted with a random key. The table shows the percentage of keys recovered.

The most-common-letter method is the weakest, reaching only 79.6% with 200 letters, because E is not always the most frequent letter in a short text. Chi-square reaches 99.9% at 50 letters. The bigram score needs the least text (96.7% at 10 letters), because it uses the order of the letters and not only their frequencies.

Limitations. The attack is unreliable on very short texts: with 5 letters even the bigram score finds the key only about 74% of the time. It also fails when the text is unusual: the sentence "Jazz quiz fuzz box zip" was decrypted incorrectly by all three methods. In addition, the language must be known and the text must use a single Caesar key. In a further test, the English model still decrypted an Italian sentence correctly with chi-square and bigrams, but this is a single example.

6. Attack on the toy ECC scheme

An attacker knows Q, R and the ciphertext. Since d can only be 1 to 8, the attacker computes G, 2G, 3G, … until the result equals Q. This happened at d = 5 after 5 attempts. Then S = dR gives the key stream and the message Attack at dawn is recovered. Q is not even necessary: S must be one of the 8 points of the curve, and trying all of them produces exactly one readable message.

Comparison with the Caesar attack. The Caesar attack uses the statistics of the message, so it can fail and works better on longer texts. The ECC attack uses only the public key and the small key space. It is exact, because dG either equals Q or not, and it works for any message of any length.

Why it does not work on a real key. A real private key is a number of about 2256 possibilities, so exhaustive search is impossible. The faster baby-step giant-step method still needs about 2128 = 3.4 × 1038 steps: at 1012 steps per second this takes about 1.1 × 1019 years and needs a similar amount of memory. There is also no statistical shortcut, because the ciphertext looks random. The only real difference between the toy scheme and a secure one is the size of the key.

Other weaknesses.

  • From the small key space: the one-time key r is also between 1 and 8, so it can be found from R in the same way.
  • From the design: the ciphertext is not authenticated. Knowing that the message contains "dawn", the ciphertext was modified so that the receiver decrypted Attack at dusk without any warning. This would also work with a full-size key and could be prevented with a message authentication code.
  • From the design: if the same r were used for two messages, both would use the same key stream, and the XOR of the two ciphertexts would equal the XOR of the two messages.
